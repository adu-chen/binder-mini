# 产品定义与需求边界

## 1. 产品定义

Binder Mini 是面向 GitHub 开源开发的本地优先 AI 文档编辑器最小核心。

用户选择一个本地目录作为 workspace，在应用内浏览、编辑文档，并通过 Agent 对话请求 AI 生成文档修改建议。AI 对内容类修改必须生成 diff，用户接受后才写入文件，拒绝后不得改变文件内容。

## 2. 目标用户

1. 需要 AI 辅助编辑本地文档的个人用户。
2. 希望基于本地优先架构二次开发 AI 编辑工具的开发者。
3. 需要可审计 diff 流程的开源项目维护者。

## 3. 核心需求

### 3.1 Workspace

- 用户可以打开一个本地目录作为 workspace。
- 文件操作、搜索、diff、上下文读取必须限制在当前 workspace 内。
- 应用记录最近打开的 workspace。

### 3.2 Editor

- 用户可以打开并编辑 md/txt 文件。
- 非 md/txt 文件可作为只读文本打开。
- 用户保存时，编辑器内容写入 ActiveFile。

### 3.3 Agent

- 用户可以配置 AI Provider 并发送对话消息。
- Agent 可以调用工作区工具读取、搜索、创建、移动、重命名或删除文件。
- Agent 的内容编辑工具必须生成 diff，不得直接写入文档内容。

### 3.4 Diff Review

- AI 内容修改以 pending diff 形式出现。
- 用户可以单条接受或拒绝 diff。
- 接受后写入文件；拒绝后丢弃候选修改。
- diff 进入终态后不得继续执行接受或拒绝动作。

## 4. 明确不做

- 多人协同编辑。
- 云端文件同步或云服务。
- Office 套件。
- 知识库平台。
- 插件市场。
- 通用聊天机器人。

## 5. 验收边界

MVP 通过以下场景视为完成：

1. 打开本地 workspace。
2. 打开并编辑 md/txt 文件。
3. 配置 Provider 并发送对话。
4. Agent 对 ActiveFile 生成 PendingDiff。
5. 用户接受 diff 后文件内容变化。
6. 用户拒绝 diff 后文件内容不变化。
